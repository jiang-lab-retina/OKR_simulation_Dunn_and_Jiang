# OKR simulation: motion and optotype models with simulated scotomas

Code for the computational models in **"Reflexive eye movements detect vision loss before perceptual visual tests"** (Harris et al., submitted): Fig 4a–l and Fig S5a–c.

- **Motion estimation:** moving dots and drifting gratings, degraded by scotoma masks with or without Gaussian blur. A Lucas–Kanade optic-flow model estimates the speed (Fig 4a–h), and a global likelihood over direction estimates the direction (Fig S5).
- **Orientation discrimination:** a tumbling-E optotype with the same scotoma masks, without or with blur. Template matching by normalised cross-correlation estimates the orientation (Fig 4i–l).

Every stimulus is generated by the code from fixed seeds, so no data files are needed. Fig 4h compares the model with human OKR data (Fig 1b). That human data isn't included; the panel draws the simulation alone unless the data are supplied (see [Fig 4h](#fig-4h-human-okr-data)).

## Contents

```
src/okr_models/
  params.py      every model parameter, as stated in the paper's Methods and legends
  stimuli.py     moving dots, sinusoidal gratings, scotoma masks, the optotype E
  motion.py      image derivatives, Lucas–Kanade speed, MAP direction (Methods, Motion estimation)
  optotype.py    template matching and confidence (Methods, Orientation discrimination)
  simulate.py    the conditions behind each panel; resumable runs
  figures.py     Fig 4 and Fig S5, with every plotted value written to JSON
  cli.py         the okr-models command
pyproject.toml, uv.lock, requirements.txt    exact dependency versions
```

## System requirements

- **Software:** Python 3.12. Dependencies, pinned in `uv.lock` and `requirements.txt`: numpy 2.2.6, scipy 1.18.1, opencv-python-headless 4.11.0.86 and matplotlib 3.10.8.
- **Operating system:** tested on macOS 27 (Apple silicon, 16 cores). The code is pure Python with standard wheels, so it should also run on Linux and Windows.
- **Hardware:** no special hardware. The runs are CPU-bound and use one process per core; memory stays under about 1 GB.

## Installation

With [uv](https://docs.astral.sh/uv/) (recommended; it installs Python 3.12 if needed):

```bash
git clone https://github.com/jiang-lab-retina/OKR_simulation_Dunn_and_Jiang.git
cd OKR_simulation_Dunn_and_Jiang
uv sync --frozen
```

Or with pip, in a Python 3.12 virtual environment:

```bash
python -m pip install -r requirements.txt
python -m pip install -e .
```

Typical install time: under a minute with uv, a few minutes with pip.

## Demo

```bash
uv run okr-models demo          # or: okr-models demo
```

The demo computes one mask realisation (seed 100) for four conditions:
- dots, radius-3 window, blur σ = 10;
- dots, R_w = 105 px, σ = 10;
- an 8-cycle grating, R_w = 120 px, σ = 10;
- the E with σ = 10.

It prints the speed, direction error or confidence at 0 %, 50 % and 95 % scotomas, and checks them against the values of the full run. Expected output ends with `demo matches the expected values`. Typical run time: DEMO_TIME on 15 worker processes.

## Reproducing Fig 4 and Fig S5

```bash
uv run okr-models run            # all conditions, 51 mask realisations each (resumable)
uv run okr-models figures        # figures/Fig4.{png,pdf,svg}, figures/FigS5.{png,pdf,svg}, figures/plotted_values.json
```

`run` writes `results/<condition>/seed_<s>.npz` and skips realisations that are already done, so an interrupted run can simply be restarted. It uses all but one core by default (`--workers N`).

Total run time: about 55 minutes on 15 worker processes (Apple silicon, 16 cores), including about 3 minutes to generate the 51 mask realisations on first use. Most of it is the radius-3 window, which has about 260,000 windows per frame stack. To compute one figure's conditions only, use `--figure 4a 4b-d 4e 4f-h 4i-l S5`; to use fewer mask realisations for a quick look, use `--seeds 100-110`.

### Model settings (paper Methods)

| | Setting |
|---|---|
| Image size | 1024 × 1024 px; movies of 9 frames at 90 frames/s |
| Dots | 300 dots, diameter 39 px, moving up at 13.33 px/frame (ground-truth speed), each visible for 150–200 ms then invisible for 150–200 ms; seed 12345 |
| Gratings | sinusoidal, 2, 4, 8, 16 and 32 cycles per image width, drifting right at 13.33 px/frame |
| Scotomas | discs of radius 40 px at random positions; 20 levels (0, 5, …, 95 % of the image); 51 independent realisations (seeds 100–150); masked pixels are set to 0 (motion) or to the grey background (optotype) |
| Blur | Gaussian, σ in px, applied before the scotomas |
| Lucas–Kanade | central differences; windows of radius 3 px with stride 2 px (Fig 4a–d, S5), R_w = 120 px with stride 120 px (Fig 4e), R_w = 105 px with stride 110 px (Fig 4f–h); windows with λ_min(M) < 0 or \|det M\| < 10⁻¹² discarded; reported speed ‖ū‖ of the mean flow |
| Direction | likelihood over direction with speed marginalised, σ = 0.05, 0.25° grid, MAP estimate; error \|θ̂ − θ_GT\| with θ_GT = 90° (dots) |
| Contamination model (Fig 4e–h) | y(p) = a₀(1 − p)e^(−kp) + αp, with a₀ fixed to the measured normalised speed at 0 % and the two parameters k and α fitted by least squares |
| Optotype | E of 640 × 800 px (strokes 160 px) at 0°, 90°, 180° and 270°, grey background 0.5; σ = 0, 10, 100 px; confidence = softmax (temperature 0.05) of the four template correlations, at the true orientation |

All values are in `src/okr_models/params.py`.

### Fig 4h: human OKR data

The observed OKR curve in Fig 4h is human data (Fig 1b), available from the corresponding authors on reasonable request. With the data as a CSV file, draw it with:

```bash
uv run okr-models figures --okr-csv okr_simulated_scotomas.csv
```

CSV layout: first row `scotoma_fraction,<f1>,<f2>,...` (scotoma coverage as fractions), then one row per subject `<id>,<gain at f1>,<gain at f2>,...`. The mean and SD (n − 1) across subjects are divided by the mean at the smallest coverage.

## Notes

- **Numerical reproducibility:** NumPy's linear-algebra backend differs between platforms (OpenBLAS, Apple Accelerate, MKL). Results agree across backends to floating-point rounding (relative differences below 10⁻⁷ in our checks), not bit for bit.
- **Gratings at 0 % scotomas (Fig 4a, 4e):** an unmasked drifting grating varies along one axis only, so every Lucas–Kanade window has a singular structure tensor (det M = 0) and is discarded. The reported speed at 0 % is therefore 0 for every grating (the aperture problem in its extreme form). In Fig 4e the contamination model's a₀ is fixed to this measured baseline, so for the gratings the fitted curve reduces to y = αp (k is undefined and reported as `null` in `plotted_values.json`).
- **Differences from the submitted Fig 4a and 4e:** these two panels follow the paper's text, which describes sinusoidal gratings, scotoma levels from 0 %, and a two-parameter contamination model. The submitted version of the panels used square-wave gratings, started the gratings at 5 % (with a 1 % random-pixel loss in place of 0 %), and fitted a₀ as a third parameter. All other panels reproduce the submitted figures.
